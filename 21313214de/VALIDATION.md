# Проверка пакета Debris

Проверено 10.09.2026 на Windows, Python 3.14.7.

- Все Python-файлы проходят проверку синтаксиса.
- 57 автоматических тестов пройдены, без пропусков.
- Миграция выполнена дважды на копии bot.db из исходного 456.zip. Существующие
  столбцы и данные сохранены; license_id добавлен до индексов; резервная копия создана.
- Проверены создание лицензии, продление, установка срока, блокировка,
  сброс устройства, отзыв после возврата оплаты и сохранение блокировки при переносе.
- Проверены одновременные события оплаты, потерянный ответ создания/продления,
  недоступность Cloudflare, перезапуск бота и повтор отправки после ошибки Telegram.
- Полный обработчик оплаты с имитацией внешних сервисов выдаёт Cloudflare DBR
  и JAR с нужным HTTPS-адресом; повтор события не начисляет срок дважды.
- main() достигает polling и освобождает ресурсы с имитацией Telegram/Cloudflare.
- Настоящий процесс python bot.py --check завершился успешно с тестовыми настройками,
  временной базой и кэшем, без сетевых запросов. Проверены понятная ошибка при пустом
  BOT_TOKEN и защита от одновременного второго процесса с той же базой.
- Интегрированный JAR проверен на CRC и отсутствие повторяющихся записей: 719 записей.
  От приложенного JAR отличается только debris-license-defaults.properties.
  Все классы и остальные ресурсы побайтно совпадают.
- Итоговый ZIP исключает реальные .env, базы, резервные копии, журналы и кэш.
  Проверено отсутствие исходных значений токенов/секретов в файлах и внутри JAR.

Зависимости: aiogram 3.31.0, SQLAlchemy 2.0.52, aiosqlite 0.22.1,
python-dotenv 1.2.3, aiohttp 3.14.3 — версии из requirements.txt установлены
в среде проверки. Сборка Docker и установка на удалённый хост не выполнялись.

Cloudflare в тестах имитирует контракт DBR-v1 из предыдущей переписки. Действующий
Worker и его секреты не менялись. Живой полный цикл с реальными платежами,
Telegram, авторизацией ADMIN_API_KEY и Minecraft не запускался. Он проверяется
после настройки хоста. README_RU.md содержит команды запуска и онлайн-проверки.

Повтор тестов: python -m unittest discover -s tests -p "test_*.py" -v
Для двух проверок старой БД задайте TEST_UPLOADED_DB и TEST_LEGACY_DB на путь к своей
резервной копии. Без этих переменных две проверки будут пропущены; тесты сами
работают с временными копиями и не меняют указанный оригинал.
