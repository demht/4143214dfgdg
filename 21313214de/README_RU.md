# Debris — полный серверный пакет для хостинга

В архиве весь проект из `456.zip`, баннер, тесты и `Debris-1.21.8-integrated.jar`.
Рабочий адрес лицензий уже установлен:
`https://debris-api.steamdemhr.workers.dev`.

## Запуск на хостинге

1. Распакуйте архив и откройте папку `server`.
2. Скопируйте `.env.example` в `.env`. Заполните три поля:
   - `BOT_TOKEN` — токен вашего Telegram-бота из BotFather.
   - `ADMIN_IDS` — ваш числовой Telegram ID; несколько ID разделяются запятой.
   - `LICENSE_ADMIN_API_KEY` — значение уже существующего секрета `ADMIN_API_KEY` в Worker `debris-api`.
3. Установите зависимости из `requirements.txt`, проверьте настройки и запустите бота.

Linux / обычный Python-хостинг (Python 3.14):

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Заполните .env в редакторе панели хостинга.
.venv/bin/python bot.py --check
.venv/bin/python bot.py --check --online
sh start.sh
```

Если панель отдельно спрашивает команду установки: `pip install -r requirements.txt`.
Команда запуска: `python bot.py`. Рабочая папка: `server`.
Переменные можно задать в панели хостинга вместо `.env`; они имеют приоритет.
В панели включите автоматический перезапуск процесса.

Windows: запустите `install_dependencies.bat`, заполните `.env`, затем `start.bat`.
Проверка: `start.bat --check` или `start.bat --check --online`.

Docker:

```sh
cp .env.example .env
# Заполните .env.
docker compose build
docker compose run --rm debris-bot python bot.py --check --online
docker compose up -d
```

Docker-файлы включены; сборка Docker в этой среде не выполнялась.

## Оплата и выдача

`PAYMENTS_ENABLED=1` включает новые покупки. Telegram Stars используют токен бота.
Для оплаты картой / СБП заполните оба поля: `PLATEGA_MERCHANT_ID` и `PLATEGA_SECRET`.
При пустых полях кнопка оплаты картой скрыта. По умолчанию бот сам проверяет статусы
Platega, поэтому входящий порт для платежей не требуется.

Сохранены исходные тарифы и промокоды. У тарифа 180 дней цена Stars равна нулю:
для его покупки нужна настроенная Platega либо изменение `TARIFFS`.
Чтобы временно закрыть новые покупки, поставьте `PAYMENTS_ENABLED=0` и перезапустите
бота. Подтверждённые оплаты и очередь выдачи продолжат обрабатываться.

После подтверждения оплаты бот создаёт или продлевает лицензию в Cloudflare и
выдаёт покупателю JAR вместе с настоящим `DBR-...`. Заказ отмечается выданным после
успешной отправки файла. При сбое Cloudflare или Telegram заказ остаётся в очереди.
Для продления заранее сохраняется конечный срок: повтор после потерянного ответа
не прибавляет весь оплаченный период ещё раз. Часы хостинга должны быть синхронизированы.

В Telegram: `/admin` открывает админку. Доступны продление, установка срока, сброс
устройства и блокировка. `/license TELEGRAM_ID 30d` выдаёт лицензию вручную и возвращает
ID администратору. Если у пользователя уже есть лицензия, команда сохраняет её срок;
для изменения срока используйте админку. Команды управления доступны только `ADMIN_IDS`.

Лицензии проверяются модом непосредственно в Cloudflare. Локальный API выключен:
`LICENSE_API_ENABLED=0`, `LICENSE_ALLOW_LOCAL_HTTP=0`. Настраивать порт 8081 не нужно.
Worker должен поддерживать уже установленный DBR-v1 протокол, включая `/health` и
`/api/admin/v1/licenses/{create,get,extend,set-duration,reset-device,set-blocked}`.
Код Worker на Cloudflare этот архив не меняет.

## Данные и перенос старого сервера

Настоящие `.env`, базы, резервные копии, кэш и журналы в ZIP не включены.
При первом запуске создаётся новая база `data/bot.db`. Храните папку `data` на
постоянном диске: там находятся заказы, история начислений и очередь выдачи.
В Docker эта папка подключена как постоянный том. Запускайте один экземпляр бота;
защита от второго процесса действует для одной и той же базы.

Если переносите действующий сервер, остановите старый процесс и сохраните его
папку. В новой папке, до создания `.env` и базы, можно выполнить:

```sh
python prepare_existing.py /path/to/old/server
```

Скрипт копирует настройки, базу и предыдущие релизы, оставляя исходную папку целой.
После копирования задайте `LICENSE_ADMIN_API_KEY`, проверьте `DB_PATH` и выполните
`python bot.py --check --online`. Скрипт переноса использует `DB_PATH=bot.db`;
при Docker перенесите эту базу в `data/bot.db`, как указано в `compose.yaml`.
Миграция обновляет старые столбцы до создания индексов и сохраняет резервную копию.
Повторная миграция не переигрывает доставленные заказы.

Старые записи основной таблицы `licenses` с действующим сроком импортируются при
обращении к лицензии, если её ещё нет в Cloudflare; DBR и оставшийся срок сохраняются.
Отдельные таблицы `debris_*` раннего сервиса сохраняются без изменения. Их содержимое
автоматически в D1 не переносится. Статистика списка покупателей использует локальный
кэш; карточка лицензии получает актуальные сведения из Cloudflare.

`license_api.py`, `license_service.py`, `license_admin.py`, `start_local_api.bat` и
старый `debris-release.jar` сохранены из полного проекта для совместимости.
Рабочий запуск — `bot.py`; выдаваемый файл задаёт `MOD_FILE_PATH`.
В поставляемом интегрированном JAR изменён только публичный адрес в properties-ресурсе;
классы и остальные ресурсы совпадают с приложенным модом. Исходные файлы пользователя
остались на месте. Хэши и состав находятся в `PACKAGE_MANIFEST.json`.

## Проверки

`python bot.py --check` проверяет обязательные настройки, миграцию, баннер и JAR,
не обращаясь к внешним сервисам. Флаг `--online` дополнительно проверяет доступность
Worker и админский ключ чтением лицензии администратора. Проверка не создаёт лицензий
и не отправляет сообщения. При обычном запуске адрес и ключ также проверяются до polling.

Результаты локальных тестов — в `VALIDATION.md`. Реальные платежи, запуск Minecraft,
авторизация вашим секретом в Cloudflare и запуск на конкретном хостинге не выполнялись.
После настройки хоста проверьте покупку, получение JAR, активацию ID и продление.
